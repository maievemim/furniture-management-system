# ระบบการจัดการการวางเฟอร์นิเจอร์เสมือนจริงผ่านเว็บไซต์

**Web-based Virtual Furniture Placement Management System**

โครงงานระดับ ปวช.3/3 สาขาเทคโนโลยีธุรกิจดิจิทัล วิทยาลัยอาชีวศึกษานครปฐม
พัฒนาให้ **บริษัท เรืองศิลป์เฟอร์นิแลนด์ จำกัด**

ลูกค้าค้นหาสินค้าด้วยรูปภาพ (AI) สร้างห้อง 3 มิติตามขนาดจริง วางเฟอร์นิเจอร์ของร้านที่มีขนาดเท่าของจริง ดูราคารวม บันทึกและแชร์ห้อง และส่องสินค้าในห้องจริงแบบ AR ผ่านกล้องมือถือ โดยไม่ต้องติดตั้งแอป
ฝั่งผู้ดูแลจัดการสินค้า อัปโหลดโมเดล 3D ดูรายงานความนิยมสินค้า และดูผลประเมินความพึงพอใจ

### สร้างโมเดล 3D จากแม่แบบ (ไม่ต้องมีไฟล์ .glb)

ร้านเพิ่มสินค้าที่ยังไม่มีไฟล์ 3D ได้เอง ระบบสร้างโมเดลขนาดเท่าของจริงพร้อมรูปสินค้าให้ในเบราว์เซอร์ ไม่เสียเงินและไม่ต้องใช้โปรแกรมอื่น

**วิธีใช้**
1. หน้า `/admin` → กด **"+ เพิ่มสินค้า"** แล้วกรอกรหัส ชื่อ และราคา
2. ช่อง **โมเดล 3D** → เลือก **"สร้างจากแม่แบบ"**
3. เลือกแม่แบบที่ใกล้กับสินค้าที่สุด
4. กรอกขนาด กว้าง × ลึก × สูง (ซม.) ตามของจริง หรือกด **"ใช้ขนาดตัวอย่าง"** เพื่อเริ่มจากขนาดมาตรฐาน
5. ปรับตัวเลือกของแม่แบบ และเลือก **วัสดุหลัก** กับ **วัสดุรอง** (ขา/โครง/มือจับ) จาก 9 สี ได้แก่ ไม้อ่อน ไม้เข้ม ขาว ดำ เทา ผ้าเบจ ผ้าเทา ผ้ากรมท่า ผ้าเขียว
6. ดูตัวอย่าง 3D ทางขวา (ลากเพื่อหมุน) ภาพจะเปลี่ยนตามทุกการปรับ
7. กด **บันทึก** ระบบจะทำต่อให้อัตโนมัติดังนี้
   - สร้างไฟล์ `.glb` และอัปโหลด
   - ถ้าไม่ได้เลือกรูปสินค้า จะใช้ภาพจากโมเดลเป็นรูปสินค้า (พื้นหลังโปร่งใส)
   - สร้างข้อมูล AI ให้ค้นหาด้วยรูปเจอ
8. สินค้าใหม่ใช้ได้ทันทีในแคตตาล็อก ห้องจัด 3D และปุ่มดู AR

**แม่แบบที่มี**

| แม่แบบ | เหมาะกับ | ปรับได้ | ขนาดตัวอย่าง (ซม.) |
| --- | --- | --- | --- |
| ตู้ / ลิ้นชัก | ตู้เสื้อผ้า ตู้ลิ้นชัก ตู้วางทีวี ตู้ข้างเตียง | หน้าตู้แบบบานเปิดหรือลิ้นชัก 1–6 ช่อง, ใส่รูปถ่ายหน้าตู้ได้ | 80 × 45 × 120 |
| ชั้นวาง | ชั้นหนังสือ ชั้นโชว์ ชั้นวางของ | จำนวนชั้น 2–8, มีหรือไม่มีแผ่นหลัง | 80 × 30 × 180 |
| โต๊ะ 4 ขา | โต๊ะกลาง โต๊ะทำงาน โต๊ะอาหาร | มีหรือไม่มีคานใต้โต๊ะ | 120 × 60 × 75 |
| โต๊ะกลม / สตูล | โต๊ะกลม โต๊ะข้าง สตูล | ขาเสาเดี่ยวหรือ 4 ขา (กว้างกับลึกต่างกันจะเป็นวงรี) | 80 × 80 × 74 |
| เก้าอี้ | เก้าอี้ทานอาหาร เก้าอี้ทำงานแบบมีพนัก | สีเบาะและสีขา | 45 × 52 × 90 |
| โซฟา | โซฟาทรงเหลี่ยม | จำนวนที่นั่ง 1–4 | 200 × 90 × 80 |
| เตียง | เตียงมีหัวเตียง (หัวเตียงอยู่ด้านหลัง) | สีโครงเตียงและสีผ้าห่ม | 160 × 210 × 100 |

**เคล็ดลับ**
- กรอกขนาดจากของจริงเสมอ เพราะระบบใช้ตัวเลขนี้ทั้งในห้อง 3D และ AR
- รูปหน้าตู้ควรถ่ายตรงๆ แล้วครอปให้เหลือเฉพาะหน้าตู้ ระบบจะยืดรูปเต็มหน้าตู้
- โมเดลจากแม่แบบหน้าตาเรียบง่าย ถ้าสินค้าทรงซับซ้อน (โซฟาโค้ง เก้าอี้บุนวม) ควรใช้ไฟล์ `.glb` จากการสแกนหรือโมเดลสำเร็จรูปแทน
- แก้สินค้าภายหลังแล้วเลือกแม่แบบใหม่ได้ โมเดลเดิมจะถูกแทนที่ เพราะระบบไม่ได้จำค่าที่เลือกไว้ครั้งก่อน

### กฎสำคัญ

- **ขนาดเท่าของจริงเสมอ** ระบบอ่านขนาดจากฐานข้อมูล (ซม.) แล้วปรับโมเดลให้ตรง ผู้ใช้ย่อหรือขยายเฟอร์นิเจอร์ไม่ได้ และ AR ตั้ง `ar-scale="fixed"`
- **ไม่มีไฟล์ 3D ก็สร้างโมเดลได้** เลือก "สร้างจากแม่แบบ" ในฟอร์มเพิ่มสินค้า ระบบสร้างโมเดลขนาดเท่าของจริงและรูปสินค้าให้ในเบราว์เซอร์ (ไม่เสียเงิน)
- **สินค้าที่ยังไม่มีโมเดล 3D** เพิ่มได้โดยไม่ต้องอัปโหลด `.glb` ในห้อง 3D จะแสดงเป็นกล่องขนาดจริงแทน (ยังวางและคิดราคาได้) แต่จะไม่มีปุ่มดู AR จนกว่าจะอัปโหลดโมเดล
- ราคารวมคำนวณจากราคาในฐานข้อมูลทุกครั้ง ไม่เก็บราคาไว้ในห้องที่บันทึก
- AR แสดงทีละชิ้น ส่วนการจัดทั้งห้องทำในโหมด 3D

## เทคนิคและข้อจำกัดของแต่ละฟีเจอร์

### 1. แคตตาล็อกและการดูโมเดล 3D (`/catalog`)
**เทคนิค**
- โหลดรายการสินค้าจากตาราง `products` ผ่าน Supabase client ค้นหาด้วยชื่อหรือรหัสโดยกรองในเบราว์เซอร์
- หน้าต่างดู 3D ใช้ `<model-viewer>` โหลดไลบรารีแบบ dynamic import เฉพาะตอนกดดูครั้งแรก หน้าแคตตาล็อกจึงไม่ช้า
- หน้าที่ใช้ไลบรารี 3D หนักๆ (จัดห้อง, ห้องที่แชร์, แอดมิน) แยกโหลดด้วย `React.lazy`

**ข้อจำกัด**
- ค้นหาได้แค่ชื่อและรหัสสินค้า ยังไม่มีหมวดหมู่ ตัวกรองราคา หรือการแบ่งหน้า ถ้าสินค้ามีหลายร้อยชิ้นจะโหลดช้าลง

### 2. จัดห้อง 3D ตามขนาดจริง (`/planner`)
**เทคนิค**
- ฉาก 3D ใช้ three.js ผ่าน `@react-three/fiber` หน่วยในฉากเป็นเมตร ฐานข้อมูลเก็บเป็นซม. แล้วหาร 100
- `Furniture.jsx` วัดกรอบ (bounding box) ของโมเดลด้วย `THREE.Box3` แล้วปรับ scale แต่ละแกนให้ตรงกับ กว้าง/สูง/ลึก ในฐานข้อมูล และวางก้นโมเดลให้แตะพื้นพอดี
- การลาก: ยิงเส้น (raycast) จากเมาส์ไปตัดระนาบพื้น y = 0 ใช้ pointer capture และปิดการหมุนกล้อง (`OrbitControls`) ระหว่างลาก
- กันหลุดนอกห้อง: บีบค่าตำแหน่ง (clamp) ทั้งระหว่างลาก ตอนปล่อยเมาส์ ตอนหมุน และตอนย่อขนาดห้อง โดยคิดกรอบฐานหลังหมุนแล้ว
- ชิ้นใหม่หาที่ว่างให้อัตโนมัติ: ไล่หาจากกลางห้องออกไปทีละ 25 ซม. จนเจอจุดที่ไม่ทับชิ้นอื่น
- เก็บสถานะห้องด้วย zustand เก็บเฉพาะ id สินค้าและตำแหน่ง ไม่เก็บราคา

**ข้อจำกัด**
- ห้องเป็นสี่เหลี่ยมผืนผ้าเท่านั้น กว้างและยาว 1–30 ม. สูง 2–6 ม. ยังไม่มีประตู หน้าต่าง เสา หรือผนังรูปทรงอิสระ (อยู่นอกขอบเขตโครงงาน)
- หมุนได้ทีละ 90° และวางได้บนพื้นเท่านั้น วางของซ้อนบนโต๊ะหรือแขวนผนังไม่ได้
- ย่อหรือขยายเฟอร์นิเจอร์ไม่ได้ (ตั้งใจ เพื่อให้ขนาดเท่าของจริงเสมอ)
- ถ้าสัดส่วนของไฟล์โมเดลต่างจากขนาดในฐานข้อมูล หรือโมเดลหันผิดแกน โมเดลจะถูกยืดจนดูบิดเบี้ยว
- เฟอร์นิเจอร์หลายชิ้นที่ใช้โมเดลละเอียดอาจทำให้มือถือรุ่นเก่ากระตุก

### 3. เครื่องมือช่วยประเมินขนาด (วัตถุประสงค์ 2.2)
**เทคนิค**
- ป้ายขนาด กว้าง × ลึก × สูง เหนือชิ้นที่เลือก ใช้ `Html` ของ drei
- ระยะห่างจากผนัง 4 ด้าน คำนวณจากตำแหน่งและกรอบฐานหลังหมุน (`wallGaps` ใน `src/lib/geometry.js`)
- เตือนเมื่อวางทับกัน ใช้การชนกันของกรอบสี่เหลี่ยมแนวแกน (AABB) ยอมให้ชิดกันพอดีได้ 5 มม. (`findOverlaps`)
- พื้นที่ที่ใช้ = ผลรวมพื้นที่ฐานของทุกชิ้น เทียบกับพื้นที่ห้อง

**ข้อจำกัด**
- ทุกการคำนวณใช้กรอบสี่เหลี่ยมรอบชิ้น ไม่ใช่รูปทรงจริง เช่น โต๊ะกลมหรือโซฟาตัว L จะถูกนับเหมือนกล่องสี่เหลี่ยม
- พื้นที่ที่ใช้ไม่หักส่วนที่วางทับกัน และไม่คิดพื้นที่ทางเดินหรือระยะเปิดประตูตู้

### 4. สินค้าที่ยังไม่มีโมเดล 3D
**เทคนิค**
- ไฟล์ `.glb` ไม่บังคับ ถ้าไม่มี ห้อง 3D จะแสดงกล่องโปร่งแสงขนาดเท่าของจริงแทน (`BoxModel` ใน `Furniture.jsx`) ยังวาง คิดราคา และตรวจระยะได้ครบ

**ข้อจำกัด**
- ไม่มีปุ่มดู AR จนกว่าจะอัปโหลดโมเดล และลูกค้าเห็นแค่กล่อง ไม่เห็นหน้าตาสินค้าในห้อง 3D

### 4.1 สร้างโมเดล 3D จากแม่แบบ (หน้าแอดมิน)
**เทคนิค**
- แม่แบบเฟอร์นิเจอร์พื้นฐาน 7 แบบ: ตู้/ลิ้นชัก, ชั้นวาง, โต๊ะ 4 ขา, โต๊ะกลม/สตูล, เก้าอี้, โซฟา, เตียง (`src/lib/modelTemplates.js`)
- ประกอบโมเดลจากรูปทรงพื้นฐานของ three.js (กล่อง, กล่องขอบมน `RoundedBoxGeometry`, ทรงกระบอก) ตามขนาด กว้าง/ลึก/สูง ที่กรอก กรอบของโมเดลเท่ากับขนาดจริงพอดี (มี test ตรวจทุกแม่แบบ) ห้องจัด 3D จึงไม่ต้องยืดโมเดล
- ปรับได้: จำนวนบาน/ลิ้นชัก, จำนวนชั้น, แผ่นหลัง, คานใต้โต๊ะ, ขาเสาเดี่ยวหรือ 4 ขา, จำนวนที่นั่งโซฟา, สีวัสดุหลักและรอง 9 แบบ (ลายไม้สร้างด้วย canvas) และใส่รูปหน้าตู้ได้
- ดูตัวอย่าง 3D หมุนได้ทันทีในฟอร์ม (`TemplateModelBuilder.jsx`) ตอนบันทึก ระบบ export เป็น `.glb` ด้วย `GLTFExporter` และเรนเดอร์รูปสินค้าพื้นหลังโปร่งใส (.webp) ให้อัตโนมัติ แล้วอัปโหลดแบบเดียวกับไฟล์ที่เลือกเอง
- ทำงานในเบราว์เซอร์ทั้งหมด ไม่เสียเงิน และไลบรารี 3D โหลดเฉพาะตอนเลือกโหมดนี้

**ข้อจำกัด**
- ได้โมเดลหน้าตาเรียบง่าย ไม่มีรายละเอียดหรือลวดลายแบบสินค้าจริง (ยกเว้นรูปหน้าตู้) ใช้แทนของทรงซับซ้อน เช่น โซฟาโค้ง เก้าอี้บุนวม หรือเตียงหัวเบาะ ได้ไม่ดี
- รูปหน้าตู้ถูกยืดเต็มหน้าตู้ ต้องครอปรูปให้เหลือเฉพาะหน้าตู้ก่อน
- ไม่ได้บันทึกค่าที่เลือกไว้ แก้สินค้าภายหลังต้องเลือกแม่แบบใหม่ และโมเดลเดิมจะถูกแทนที่

### 5. สรุปราคารวม (BOM)
**เทคนิค**
- คำนวณจากรายการในห้อง × ราคาในฐานข้อมูลทุกครั้ง (`computeBom`) จัดกลุ่มตามสินค้า แสดงราคาเป็นบาทแบบมีคอมมาด้วย `Intl.NumberFormat('th-TH')`

**ข้อจำกัด**
- ไม่เก็บราคา ณ วันที่บันทึก ถ้าร้านเปลี่ยนราคา ห้องที่แชร์ไว้จะแสดงราคาใหม่
- ไม่มีส่วนลด ค่าส่ง ภาษี ตะกร้า หรือการชำระเงิน (อยู่นอกขอบเขตโครงงาน)

### 6. บันทึกและแชร์ห้อง (`/room/:id`)
**เทคนิค**
- สร้าง id แบบ UUID ในเบราว์เซอร์ (`crypto.randomUUID`) แล้วใช้เป็นลิงก์แชร์ บันทึกลงตาราง `rooms` และ `room_items`
- เปิดลิงก์แล้วโหลดห้องพร้อมข้อมูลสินค้าด้วย join ของ Supabase กด "แก้ไขต่อ" จะคัดลอกไปหน้าจัดห้องและบันทึกเป็นห้องใหม่

**ข้อจำกัด**
- ห้องที่บันทึกแล้วแก้ไขหรือลบไม่ได้ ทุกครั้งที่แก้จะได้ลิงก์ใหม่
- ไม่มีระบบสมาชิกลูกค้า จึงไม่มีหน้า "ห้องของฉัน" ใครมีลิงก์ก็เปิดดูได้
- ใครก็สร้างห้องได้โดยไม่ต้องล็อกอิน (เปิดไว้สำหรับเดโม) จึงมีโอกาสถูกสร้างข้อมูลขยะ

### 7. ดูสินค้าในห้องจริงแบบ AR
**เทคนิค**
- ใช้ `<model-viewer>` เลือกโหมดตามเครื่องอัตโนมัติ: WebXR หรือ Scene Viewer (Android) และ Quick Look (iPhone)
- ตั้ง `ar-scale="fixed"` ให้แสดงขนาดเท่าของจริงเสมอ ผู้ใช้ย่อขยายไม่ได้

**ข้อจำกัด**
- ต้องเปิดผ่าน HTTPS บนมือถือที่รองรับ AR (Android ที่รองรับ ARCore หรือ iPhone/iPad ที่รองรับ ARKit) ใช้กับ localhost หรือคอมพิวเตอร์ไม่ได้
- แสดงได้ทีละชิ้น วางทั้งห้องใน AR ไม่ได้ (อยู่นอกขอบเขตโครงงาน)
- ความแม่นของการวางขึ้นกับแสงและพื้นผิว พื้นเรียบไม่มีลวดลายหรือแสงน้อย กล้องจะจับพื้นได้ยาก

### 8. ค้นหาสินค้าด้วยรูปภาพ (`/search`)
**เทคนิค**
- **Image Embedding:** ใช้โมเดล CLIP (`Xenova/clip-vit-base-patch32` แบบ quantized q8) ผ่าน `@huggingface/transformers` รันในเบราว์เซอร์ แปลงรูปเป็นเวกเตอร์ 512 ค่า (`src/lib/clip.js`) รูปพื้นหลังโปร่งใสจะถูกวางบนพื้นขาวก่อน
- **Vector Similarity Search:** เก็บเวกเตอร์ของรูปสินค้าในคอลัมน์ `embedding` (pgvector) ฟังก์ชัน `match_products` เรียงสินค้าตาม cosine similarity แล้วคืน 6 อันดับแรก
- **เกณฑ์ "คล้าย":** คล้ายตั้งแต่ 62% และห่างจากอันดับ 1 ไม่เกิน 10% ตั้งจากผลวัดจริง (ของชิ้นเดียวกันได้ราว 72–84% ของคนละประเภทได้ราว 45–58%) ที่ไม่ผ่านเกณฑ์จะแสดงใต้หัวข้อ "สินค้าอื่นที่อาจสนใจ"
- หน้าจัดการสินค้าสร้างเวกเตอร์ให้สินค้าใหม่หรือสินค้าที่เปลี่ยนรูปโดยอัตโนมัติ
- รูปของลูกค้าไม่ถูกอัปโหลด ส่งไปฐานข้อมูลแค่ตัวเลข 512 ค่า ไม่มีค่าใช้จ่าย API

**ข้อจำกัด**
- ครั้งแรกต้องดาวน์โหลดโมเดล AI ราว 90 MB (ครั้งต่อไปใช้แคชของเบราว์เซอร์) มือถือรุ่นเก่าอาจใช้หลายวินาทีต่อรูป
- เทียบจาก "รูปสินค้า 1 รูปต่อชิ้น" เท่านั้น รูปถ่ายจริงต่างจากรูปสินค้าที่เป็นภาพเรนเดอร์ ความคล้ายสูงสุดจึงมักอยู่ราว 70–85% ไม่ถึง 100%
- หาได้แค่ "หน้าตาคล้าย" ไม่รู้ขนาด ยี่ห้อ หรือวัสดุ รูปที่มีเฟอร์นิเจอร์หลายชิ้นจะได้ผลไม่แม่น ยังไม่มีการครอปรูป
- รองรับรูป .jpg / .png / .webp ไม่เกิน 10 MB และเกณฑ์ 62% อาจต้องปรับใหม่เมื่อมีสินค้ามากขึ้น

### 9. ระบบผู้ดูแล: จัดการสินค้าและอัปโหลดไฟล์ (`/admin`)
**เทคนิค**
- ล็อกอินด้วย Supabase Auth (อีเมลและรหัสผ่าน) หน้า `/admin/*` ส่งไปหน้าล็อกอินเมื่อยังไม่ล็อกอิน
- สิทธิ์จริงคุมที่ฐานข้อมูลด้วย Row Level Security: ทุกคนอ่านสินค้าได้ แต่เขียนได้เฉพาะผู้ที่ล็อกอิน
- ตรวจไฟล์ก่อนอัปโหลด: `.glb` ไม่เกิน 5 MB และ 4 ไบต์แรกต้องเป็น `glTF` ส่วนรูปต้องเป็น .jpg/.png/.webp ไม่เกิน 2 MB ตั้งชื่อไฟล์ใหม่ทุกครั้ง (กันเบราว์เซอร์แคชไฟล์เก่า) และลบไฟล์เก่าเมื่อถูกแทนที่
- ลบสินค้าที่อยู่ในห้องที่ลูกค้าบันทึกไว้ไม่ได้ (foreign key `on delete restrict`)

**ข้อจำกัด**
- ทุกบัญชีที่ล็อกอินได้คือแอดมิน ไม่มีการแบ่งบทบาท **ต้องปิดการสมัครสมาชิกเองใน Supabase** (Authentication → Sign In / Providers → ปิด Allow new users to sign up) ไม่อย่างนั้นใครสมัครได้ก็แก้สินค้าได้
- ไม่บีบไฟล์โมเดลให้อัตโนมัติ ต้องบีบด้วย gltf-transform ก่อนอัปโหลด และระบบไม่ตรวจทิศหรือสัดส่วนของโมเดล

### 10. รายงานความนิยมสินค้า (`/admin/report`)
**เทคนิค**
- view `product_popularity` นับจำนวนครั้งที่สินค้าแต่ละชิ้นถูกวางในห้องที่บันทึก แสดงเป็นกราฟแท่ง (recharts) และตาราง

**ข้อจำกัด**
- นับเฉพาะห้องที่กดบันทึก ไม่นับการเปิดดูหรือการดู AR ไม่มีตัวกรองช่วงเวลา
- ห้องที่สร้างจาก E2E test ถูกนับรวมด้วย ตัวเลขจึงสูงกว่าการใช้งานจริง

### 11. แบบประเมินผู้ใช้และผู้เชี่ยวชาญ (วัตถุประสงค์ 2.1 และ 2.3)
**เทคนิค**
- มาตราส่วนประมาณค่า 5 ระดับ คำถามทั้งสองชุดกำหนดไว้ที่ `src/lib/survey.js` และใช้ส่วนแสดงผลร่วมกัน
- สรุปผลด้วยค่าเฉลี่ย (x̄) และส่วนเบี่ยงเบนมาตรฐานของกลุ่มตัวอย่าง (S.D. หารด้วย n − 1) รายข้อ รายด้าน และภาพรวม แปลความหมายด้วยเกณฑ์ช่วงค่าเฉลี่ย (4.51–5.00, 3.51–4.50, …) ส่งออก CSV แบบ UTF-8 BOM ให้เปิดใน Excel เป็นภาษาไทยได้
- ใครก็ส่งแบบประเมินได้โดยไม่ต้องล็อกอิน แต่อ่านผลได้เฉพาะแอดมิน (RLS)

**ข้อจำกัด**
- ไม่ระบุตัวตนและไม่กันการส่งซ้ำ คนเดียวส่งหลายครั้งได้
- แก้จำนวนข้อคำถามแล้วต้องแก้ check ใน `supabase/schema.sql` ด้วย และคำตอบเก่าที่จำนวนข้อไม่ตรงจะไม่ถูกนับ

### 12. การสร้างโมเดล 3D ของทีมเอง (`scripts/make-bowl.mjs`)
**เทคนิค**
- สร้างโมเดลด้วยโค้ด three.js จากรูปถ่ายและขนาดที่วัดจริง: ตัวชามหมุนเส้นขอบด้านข้างรอบแกน (`LatheGeometry`) หูจับใช้ `TorusGeometry` แล้ว export เป็น `.glb` ด้วย `GLTFExporter` ผ่านเบราว์เซอร์ (vite + Playwright)
- ลายบนผิว: คลี่ภาพจากรูปถ่ายผิวโค้งให้แบน (ชดเชยมุมกล้องและความโค้ง) ตัดพื้นหลังออก แล้วแปะเป็นแผ่นลายโปร่งใสห่อตามผิวชาม

**ข้อจำกัด**
- เหมาะกับของทรงเรียบหรือทรงกลมสมมาตร ของทรงซับซ้อน เช่น โซฟาหรือเก้าอี้บุนวม ต้องใช้การสแกน 3D หรือ AI แปลงรูปเป็น 3D แทน
- แสงและเงาจากรูปถ่ายติดมากับลาย ลายที่เป็นเครื่องหมายการค้าใช้ได้เฉพาะทดลองภายใน

### ข้อจำกัดของระบบโดยรวม
- **ใช้บริการแผนฟรีทั้งหมด:** Supabase จะพักโปรเจกต์ถ้าไม่มีการใช้งาน 7 วัน, Storage 1 GB, Vercel Hobby
- **ต้องใช้อินเทอร์เน็ตตลอด:** ไม่มีโหมดออฟไลน์ ฟอนต์โหลดจาก Google Fonts
- **ไลบรารี 3D ขนาดใหญ่:** three.js และ model-viewer รวมหลายร้อย KB หน้าจัดห้องจึงโหลดครั้งแรกช้ากว่าหน้าอื่น
- **ข้อความหน้าเว็บเป็นภาษาไทยอย่างเดียว:** ตัวอักษรเล็กสุด 16px รองรับจอกว้างตั้งแต่ 360px
- **E2E test ใช้ฐานข้อมูลจริง:** smoke test สร้างห้องจริงทุกครั้งที่รัน (แบบประเมินดักคำขอไว้ ไม่บันทึกจริง)

## การติดตั้ง

### สิ่งที่ต้องมี

- [Node.js](https://nodejs.org) เวอร์ชัน 20 ขึ้นไป (แนะนำ 24)
- Git
- บัญชี [Supabase](https://supabase.com) (ฟรี)
- บัญชี GitHub และ [Vercel](https://vercel.com) ถ้าจะนำขึ้นออนไลน์

### 1. ดาวน์โหลดโปรเจกต์

```bash
git clone <URL ของ repository>
cd project
npm install
```

### 2. สร้างฐานข้อมูลบน Supabase

1. สร้างโปรเจกต์ใหม่ (แผน Free, Region: Southeast Asia (Singapore))
2. เมนู **SQL Editor** → วางทั้งไฟล์ [`supabase/schema.sql`](supabase/schema.sql) → **Run**
   สร้างตาราง view function สิทธิ์ (RLS) และ Storage bucket `models` ให้ครบ รันซ้ำได้ไม่เสียหาย
3. SQL Editor → วาง [`supabase/seed.sql`](supabase/seed.sql) → **Run** (สินค้าตัวอย่าง 5 ชิ้น)
4. **Authentication → Users → Add user** สร้างบัญชีแอดมิน

### 3. ตั้งค่าการเชื่อมต่อ

```bash
cp .env.example .env.local
```

เปิด `.env.local` แล้วใส่ค่า

| ตัวแปร | เอามาจาก |
| --- | --- |
| `VITE_SUPABASE_URL` | Project URL (`https://<project-id>.supabase.co`) ปุ่ม **Connect** หรือ Project Settings → Data API |
| `VITE_SUPABASE_ANON_KEY` | **Publishable key** (`sb_publishable_...`) ใน Project Settings → API Keys |
| `ADMIN_EMAIL`, `ADMIN_PASSWORD` | ไม่บังคับ ใช้เฉพาะตอนรัน E2E test ส่วนแอดมิน |

> ⚠️ ห้ามใช้ Secret key (`sb_secret_...`) หรือ service_role key ในหน้าเว็บเด็ดขาด และห้าม commit `.env.local`

### 4. อัปโหลดโมเดลและรูปตัวอย่าง

ไฟล์อยู่ใน `assets/samples/` อัปโหลดขึ้น Storage ด้วยสคริปต์ (ต้องใส่ `ADMIN_EMAIL` / `ADMIN_PASSWORD` ของบัญชีแอดมินจากข้อ 2.4 ใน `.env.local` ก่อน)

```bash
node --env-file=.env.local scripts/upload-samples.mjs
```

หรืออัปโหลดเองผ่าน Supabase → Storage → bucket `models` โดยวาง `.glb` ในโฟลเดอร์ `glb/` และรูปใน `thumbs/`

### 5. เปิดใช้งาน

```bash
npm run dev
```

เปิด http://localhost:5173/catalog ต้องเห็นสินค้า 5 ชิ้น

### 6. เปิดใช้การค้นหาด้วยรูป

ล็อกอินหน้า `/admin` → แผง **AI ค้นหาด้วยรูป** → กด **สร้างข้อมูล AI**
ระบบจะโหลดโมเดล AI (ครั้งแรกราว 90 MB) แล้วแปลงรูปสินค้าทุกชิ้นเป็นข้อมูลสำหรับค้นหา ต้องกดซ้ำทุกครั้งที่เพิ่มสินค้าใหม่หรือเปลี่ยนรูปสินค้า

## การนำขึ้นออนไลน์ (Vercel)

1. Push โค้ดขึ้น GitHub
2. Vercel → **Add New → Project** → เลือก repository (Framework: Vite)
3. **Environment Variables** ใส่ `VITE_SUPABASE_URL` และ `VITE_SUPABASE_ANON_KEY` ติ๊กทั้ง **Production** และ **Preview**
4. **Settings → Deployment Protection** ปิด Vercel Authentication เพื่อให้คนอื่นเปิดลิงก์ได้โดยไม่ต้องล็อกอิน
5. `vercel.json` ตั้ง rewrite ทุก path ไป `/` ไว้แล้ว รีเฟรชหน้าไหนก็ไม่เจอ 404

> การทดสอบ AR บนมือถือต้องใช้ HTTPS (กล้องไม่ทำงานบน `http://`) ให้ทดสอบบนลิงก์ของ Vercel ไม่ใช่ localhost

## ฐานข้อมูล

| ตาราง / ออบเจกต์ | เก็บอะไร | สิทธิ์ |
| --- | --- | --- |
| `products` | รหัส ชื่อ ราคา ขนาด (ซม.) path ของโมเดลและรูป และ `embedding` (CLIP 512 มิติ) | ทุกคนอ่าน, แอดมินเขียน |
| function `match_products` | คืนสินค้าที่รูปคล้ายที่สุด (cosine similarity ด้วย pgvector) | ทุกคนเรียกได้ |
| `rooms` | ห้องที่บันทึก (id ใช้เป็นลิงก์แชร์) ขนาดห้อง (ม.) | ทุกคนสร้างและอ่าน |
| `room_items` | ตำแหน่ง x, z และมุมหมุนของเฟอร์นิเจอร์แต่ละชิ้น | ทุกคนสร้างและอ่าน |
| `survey_responses` | คำตอบแบบประเมินความพึงพอใจ (เพศ ช่วงอายุ อุปกรณ์ คะแนน 12 ข้อ ข้อเสนอแนะ) | ทุกคนส่ง, แอดมินอ่าน |
| `expert_reviews` | แบบประเมินผู้เชี่ยวชาญ (ชื่อ/ตำแหน่งไม่บังคับ คะแนน 19 ข้อ ข้อเสนอแนะ) | ทุกคนส่ง, แอดมินอ่าน |
| view `product_popularity` | จำนวนครั้งที่สินค้าแต่ละชิ้นถูกวางในห้อง | ตาม `products` / `room_items` |
| Storage `models` | ไฟล์ `.glb` และรูปสินค้า | ทุกคนอ่าน, แอดมินอัปโหลด/ลบ |

ทุกการเปลี่ยนแปลงโครงสร้างฐานข้อมูลต้องแก้ใน `supabase/schema.sql` แล้วรันไฟล์นั้นซ้ำใน SQL Editor

## การทดสอบ

```bash
npx playwright install chromium   # ครั้งแรกครั้งเดียว
npx playwright test               # build + รันทั้งหมดบนจอ desktop และจอ 360px
BASE_URL=https://<ลิงก์ staging> npx playwright test   # ทดสอบกับเว็บที่ขึ้นออนไลน์แล้ว
```

ชุดทดสอบครอบคลุม: หน้าแรก, ขนาดของโมเดลจากแม่แบบทุกแบบ, เพิ่มสินค้าจากแม่แบบแล้ววางในห้อง, แคตตาล็อก, ค้นหาด้วยรูป (โหลดโมเดล AI จริง ต้องสร้างข้อมูล AI ในหน้าแอดมินก่อน), การจัดห้อง (smoke test: สร้างห้อง → วาง → ราคาถูก → บันทึก → เปิดลิงก์แชร์ได้ห้องเดิม), กันเฟอร์นิเจอร์หลุดนอกห้อง, ระยะห่างจากผนัง, แบบประเมิน, หน้าแอดมิน และสิทธิ์การแก้ไขผ่าน API

> test ของแบบประเมินดักคำขอไว้ ไม่บันทึกคำตอบปลอมลงฐานข้อมูลจริง ส่วน smoke test ของการจัดห้องจะสร้างห้องจริง 1 ห้องทุกครั้งที่รัน

ก่อนเปิด Pull Request เข้า `staging` ต้อง `npm run build` ผ่านและ Playwright ผ่านทั้งหมด ถ้าแก้ส่วน 3D หรือ AR ให้ทดสอบบนมือถือจริง (Android Chrome + iPhone Safari) ด้วย

## ปัญหาที่พบบ่อย

| อาการ | วิธีแก้ |
| --- | --- |
| หน้าเว็บขึ้น "ยังไม่ได้ตั้งค่าการเชื่อมต่อฐานข้อมูล" | ยังไม่มี `.env.local` หรือใส่ค่าไม่ครบ แก้แล้วรัน `npm run dev` ใหม่ (บน Vercel ต้อง Redeploy) |
| โหลดสินค้าไม่ได้ทั้งที่ตั้งค่าถูก | Supabase พักโปรเจกต์เมื่อไม่มีการใช้งาน 7 วัน เข้า Dashboard แล้วกด **Restore** |
| หน้าผลประเมินขึ้น "โหลดผลประเมินไม่สำเร็จ" | ยังไม่ได้รัน `supabase/schema.sql` เวอร์ชันล่าสุด (ตาราง `survey_responses` และ `expert_reviews`) |
| ค้นหาด้วยรูปแล้วขึ้น "ยังไม่พบสินค้าที่คล้าย" | แอดมินยังไม่ได้กด "สร้างข้อมูล AI" ในหน้าจัดการสินค้า |
| ผลค้นหาด้วยรูปไม่ตรง | ใช้รูปที่เห็นเฟอร์นิเจอร์ชิ้นเดียวชัดๆ รูปทั้งห้องที่มีหลายชิ้นจะได้ผลไม่แม่น |
| ปุ่ม AR ไม่ขึ้น | ต้องเปิดบนมือถือผ่าน HTTPS และสินค้านั้นต้องมีไฟล์ `.glb` |
| อัปโหลดโมเดลไม่ได้ | ไฟล์ต้องเป็น `.glb` ไม่เกิน 5 MB บีบไฟล์ด้วย `npx @gltf-transform/cli optimize in.glb out.glb --compress false --texture-compress webp --texture-size 1024` (ห้ามใช้ meshopt ดู `docs/model-credits.md`) |
| รีเฟรชแล้วเจอ 404 บน Vercel | ตรวจว่ามี `vercel.json` ที่ rewrite ทุก path ไป `/` |
